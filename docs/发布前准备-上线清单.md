## 0. 选型结论（先看这一节）

几十个用户 + 个人初期 + 低预算，**不要买中国内地节点**。原因：内地节点必须完成 ICP 备案（3～22 个工作日）才能对外提供网站服务，而个人主体做「题库/教育」类内容存在被退回的风险（《互联网信息服务管理办法》第十一条把教育列入需前置审批的类别）。

推荐路线：**腾讯云轻量应用服务器 · 境外节点（新加坡/东京）+ IP 直接访问**，约 99 元/年，免备案，付款 5 分钟即可部署。第二阶段再花 ~76 元买 `.com` 域名，用 Cloudflare 免费套餐加 HTTPS。

| 方案 | 成本（首年） | 是否需要备案 | 适用阶段 | 结论 |
| --- | --- | --- | --- | --- |
| A. 本机 + 内网穿透（frp / Cloudflare Tunnel） | 0 元 | 否 | 只有自己用 | 电脑必须常开，仅作临时验证 |
| B. 境外轻量 2核2G + IP 访问 | 约 99 元 | 否 | **起步，几十人访问** | **推荐** |
| C. 境外轻量 + `.com` 域名 + Cloudflare HTTPS | 约 175 元 | 否 | 需要正式域名/手机端可信访问 | 第二阶段 |
| D. 境内轻量/ECS | 38～188 元 | **是（3～22 工作日）** | 用户上百、要求国内低延迟 | 暂不选 |

境外节点到国内延迟约 50～150 ms，几十人自用完全可接受。

## 1. 账号与合规

- [ ] 云账号完成**个人实名认证**（身份证 + 人脸），未实名不能下单。

- [ ] 确认网站内容范围：只做个人学习资料整理与练习，不开放经营性功能（支付、售卖、课程售卖）。

## 2. 服务器与网络

- [ ] 产品选**轻量应用服务器（Lighthouse）**，不要选 CVM/ECS：个人开发者的量级，轻量套餐制更省心。
- [ ] 地域选**新加坡或东京**（免备案）；境内不要选，避免卡备案。
- [ ] 规格 **2核2G / 20M 峰值 / 40G SSD / 512G 月流量**。刊例价 30 元/月（年付 85 折约 306 元），活动价常见 99 元/年，以购买页实时价为准。
- [ ] 镜像选 **Ubuntu 24.04 LTS**（不要选宝塔镜像，环境按本文命令自建更可控）。
- [ ] 记下**公网 IP**，重置并记下 **root 密码**。
- [ ] 防火墙/安全组只放行 **22、80、443**；**3001 端口绝不放行**（API 只由本机 Nginx 反代）。
- [ ] 跑上图后先加 swap：2G 内存构建前端有 OOM 风险（本地构建 3198 个模块）。

```bash
fallocate -l 2G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab
```

- [ ] 安装运行时与依赖：

```bash
apt update && apt upgrade -y
curl -fsSL https://deb.nodesource.com/setup_22.x | bash -
apt install -y nodejs nginx postgresql git
npm i -g pnpm@10.12.1
node -v   # 必须 >= 22（项目 engines 硬要求）
pnpm -v   # 10.12.1
```

## 3. 代码与配置（四个致命坑）

这几个坑是本项目实测确认过的，不处理必然上线失败：

| # | 坑 | 现象 | 正确做法 | 验收方法 |
| --- | --- | --- | --- | --- |
| ① | 构建前没设 `VITE_API_BASE_URL` | 打包后写死 `http://127.0.0.1:3001`，用户浏览器请求自己电脑，全站失败 | 构建时注入，值＝站点对外地址（同域就填 `http://你的IP` 或 `https://你的域名`） | 服务器上 `grep -o "127.0.0.1:3001" apps/web/dist/assets/*.js` 应**无输出** |
| ② | 新机器直接 `pnpm build` | 报找不到 Prisma Client | `apps/api/src/generated/prisma` 未入库（`git ls-files` 追踪数为 0），必须先 `prisma generate` | `dist/generated/prisma/client.js` 存在 |
| ③ | `WEB_ORIGIN` 与真实来源不一致 | 登录/接口被 CORS 拦截 | 精确到协议+域名+端口，多来源用英文逗号分隔 | 浏览器控制台无 CORS 报错 |
| ④ | Nginx 只配静态根 | 刷新任何子路由 404（`App.tsx` 用 `BrowserRouter`） | 加 SPA 回退 `try_files $uri /index.html` | 直接访问 `/exams/xxx` 能正常打开 |
| ⑤ | `LLM_TOKEN_ENCRYPTION_KEY` 非 32 字节 Base64 | 用户保存自带 API Token 时返回 500（`LLM_ENCRYPTION_NOT_CONFIGURED`） | 用 32 字节随机密钥的 Base64 | 登录后在设置页保存 token 成功 |
| ⑥ | `.env` 放错位置 | 启动即报环境变量校验失败 | 必须放在**仓库根目录**（`apps/api/src/config/env.ts` 按相对路径解析，构建后 `dist/config` 层级不变） | `node apps/api/dist/server.js` 能正常监听 |

生成密钥：

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"   # LLM_TOKEN_ENCRYPTION_KEY
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"      # JWT_SECRET / JWT_REFRESH_SECRET
```

生产 `.env` 模板（放在仓库根，文件名 `.env`）：

```ini
NODE_ENV=production
PORT=3001
DATABASE_URL=postgresql://exam:你的强密码@127.0.0.1:5432/exam_assistant?schema=public
JWT_SECRET=第一步生成的48字节hex
JWT_REFRESH_SECRET=另一个48字节hex
JWT_ACCESS_TTL=15m
JWT_REFRESH_TTL=7d
WEB_ORIGIN=http://你的公网IP
LLM_TOKEN_ENCRYPTION_KEY=32字节密钥的Base64
DEEPSEEK_API_KEY=
```

- [ ] `.env` 权限收紧：`chmod 600 .env`。
- [ ] `WEB_ORIGIN` 只写一个来源时是单值匹配；写多个用逗号，不加空格以外的多余字符，末尾不要带斜杠。

## 4. 数据库

- [ ] 建用户与库：

```bash
sudo -u postgres psql -c "CREATE USER exam WITH PASSWORD '你的强密码';"
sudo -u postgres psql -c "CREATE DATABASE exam_assistant OWNER exam;"
```

- [ ] 确认 Postgres 只监听本机（Ubuntu 默认 `listen_addresses='localhost'`，不要改成 `*`）。
- [ ] 执行迁移（共 3 个 migration，含 2 个 enum 类型 `question_type`、`import_status`）：

```bash
pnpm --filter @exam/api exec prisma migrate deploy
```

  prisma 7 会自动加载 `apps/api/prisma7.config.ts`（已验证），无需额外 `--config` 参数。

- [ ] 迁移结果核对：`sudo -u postgres psql -d exam_assistant -c "\dt"` 应看到 10 张表，表名为蛇形小写：`users`、`user_llm_credentials`、`refresh_tokens`、`exams`、`categories`、`questions`、`attempts`、`import_jobs`、`category_stats`、`practice_sessions`。
- [ ] 配置每日备份（保留 7 天，约占用几十 MB）：

```bash
mkdir -p /var/backups/exam
crontab -e
# 加入：
0 3 * * * pg_dump -U exam -Fc exam_assistant > /var/backups/exam/exam_$(date +\%F).dump && find /var/backups/exam -name 'exam_*.dump' -mtime +7 -delete
```

## 5. 构建与启动

```bash
git clone <你的仓库地址> /srv/exam-assistant
cd /srv/exam-assistant
# 放置 .env 到仓库根（见第 3 节）
pnpm install --frozen-lockfile
pnpm --filter @exam/api exec prisma generate          # 坑②
VITE_API_BASE_URL=http://你的公网IP pnpm build       # 坑①
```

> 2G 内存若在 `vite build` 阶段被 kill，两种解法：① 已加的 swap 生效后重试；② 改在本机 Windows 上构建，只把 `apps/web/dist` 和 `apps/api/dist` 上传到服务器（两处产物均为纯 JS，无原生二进制，跨平台可用），服务器只跑 `pnpm install --frozen-lockfile`。

常驻启动（systemd）：

```bash
useradd -r -s /usr/sbin/nologin exam || true
chown -R exam:exam /srv/exam-assistant
cat > /etc/systemd/system/exam-api.service <<'EOF'
[Unit]
Description=Exam Assistant API
After=network.target postgresql.service

[Service]
Type=simple
User=exam
WorkingDirectory=/srv/exam-assistant
EnvironmentFile=/srv/exam-assistant/.env
ExecStart=/usr/bin/node apps/api/dist/server.js
Restart=always
RestartSec=3
StandardOutput=append:/var/log/exam-api.log
StandardError=append:/var/log/exam-api.log

[Install]
WantedBy=multi-user.target
EOF
systemctl daemon-reload && systemctl enable --now exam-api
```

> `EnvironmentFile` 与 `.env` 二选一即可：`dotenv` 不会覆盖已存在的环境变量，两者同时存在也不会冲突。

Nginx（先用 IP 访问版，80 端口）：

```bash
cat > /etc/nginx/sites-available/exam <<'EOF'
server {
  listen 80;
  server_name _;
  root /srv/exam-assistant/apps/web/dist;
  index index.html;
  client_max_body_size 2m;

  location / { try_files $uri /index.html; }          # 坑④
  location /api/ {
    proxy_pass http://127.0.0.1:3001;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
  }
  location = /health { proxy_pass http://127.0.0.1:3001; }

  gzip on;
  gzip_types text/css application/javascript application/json image/svg+xml;
}
EOF
ln -sf /etc/nginx/sites-available/exam /etc/nginx/sites-enabled/exam
rm -f /etc/nginx/sites-enabled/default
nginx -t && systemctl reload nginx
```

第二阶段加域名时：Cloudflare 里 A 记录指向公网 IP，SSL/TLS 模式设 **Full**，`WEB_ORIGIN` 改成 `https://你的域名` 并重新构建前端（`VITE_API_BASE_URL` 同步换成 https 域名，坑①与坑③必须同时改）。

## 7. 发布当天的操作顺序（防止踩踏）

1. 本地确认 `pnpm build` 通过（已验证，改动后重跑）。
2. 服务器 `pnpm install` → `prisma generate` → **迁移**（`migrate deploy`）→ 再 `pnpm build`。
3. 先起 API（systemd），`curl 127.0.0.1:3001/health` 通过后再 reload Nginx。
4. 验收清单全部打勾后，再把地址发给其他人。
5. 发版时顺序固定为：`migrate deploy` → 重启 `exam-api` → reload `nginx`；回滚只回滚代码，不回滚已执行的迁移。

## 8. 容量判断与升级路径

几十个用户的负载特征：并发通常在个位数到十几个，2核2G 足够（Postgres 与 API 同机，前端是纯静态文件）。

观察指标与触发条件：

| 指标 | 观察方式 | 升级触发 |
| --- | --- | --- |
| 可用内存 | `free -h` | 长期 < 200 MB 或出现 OOM kill |
| 进程重启次数 | `systemctl status exam-api` | 一天内 Restart 多次 |
| 响应时间 | `curl -w '%{time_total}' http://IP/health` | 多次超过 1s |
| 磁盘 | `df -h` | 使用率 > 80% |

升级路径：
- 第一步：同平台升配到 2核4G（不用改架构）。
- 第二步：用户上百、要求国内低延迟时，才考虑境内节点 + 备案；此时可选境内轻量 2核4G/5M（188 元/年，可免费升配到 4核4G，含 1 次 3.5 折续费）或阿里云 ECS 经济型 e 2核2G（99 元/年，续费同价锁至 2029-03-31，限购 1 台）。**务必先拿到备案号再切域名**，备案期间域名不能对外提供访问。
- 不建议在几十人阶段上 Docker、CDN、独立数据库：收益低，运维成本高。
