# 备考助手 · 产品定义 v0.2

> 状态：核心决策已全部确认，可直接进入表设计与开发
> 定位：AI 驱动的背诵型题库自测工具（教资 / 公考 / 技术面试）
> 一句话：把一整段杂乱文本扔进去，AI 帮你变成能练的题。

---

## 1. 核心价值主张

题库产品真正的痛点不是"做题"，是**"建题"**。

手填一道题要选考试、选类目、选题型、填题干、填选项、填答案、填解析——7 个字段，每题 2 分钟。50 题就是一个下午。绝大多数自制题库死在这一步。

本产品把这一步交给 AI：粘 10 页教材重点，30 秒得到 30 道结构化题目，人只做校对。

差异点不是"有个 AI 按钮"，而是 **AI 站在数据入口上**——它决定了这个产品能不能被真正用起来。这也让项目本身有价值：非结构化输入 → 结构化输出、长任务编排、人机协同校对，这是 AI 全栈真正难的部分，不是套壳。

## 2. 用户与场景

- **单一角色**：备考者本人，自己建题、自己练。不做机构、班级、题目分享。
- **典型场景**：考前两周，把教材重点 / 往年真题 / 公众号干货粘进来，快速自测，然后反复刷错题。
- **不做的事**：不做社区、不做题库市场、不做教师端。

## 3. 决策记录（已确认）

| 决策项 | 结论 | 直接后果 |
|---|---|---|
| AI 主战场 | 导入侧：文本 → 结构化题目 | 核心链路必须有两段式：AI 解析 + 人工校对 |
| 用户模型 | 多用户 + 邮箱密码登录 | 需要 users 表；所有业务表带 user_id 做数据隔离 |
| 过关判定 | 答对一次即过关 | 必须有 attempts 答题流水表，过关 = 存在 is_correct=true 的记录 |
| 一期题型 | 单选、多选、填空、简答 | 不含算法题 / 代码题 |
| 简答判题 | AI 二值判定 + 采分点反馈 | 需要 LLM 调用层，见第 4 节 |
| 错误率口径 | 答错次数 ÷ 总作答次数 | 不用"1 − 过关率"，那个指标会饱和 |
| 错题生命周期 | 答对后移入「已订正」，可查看不计入待刷 | 保留复习痕迹，待刷数不虚高 |

## 4. 简答题 AI 判分设计

一期已确认：简答题走 **AI 二值判定 + 采分点反馈**，不用用户自评。

### 判定流程

1. 空答案或短于 5 字 → 直接判错，不发请求（省成本，也更准）
2. 构造 prompt：题干 + 参考答案 + rubric（从参考答案里抽 3–5 个采分点）
3. 一次 LLM 调用，返回结构化 JSON
4. 落库 `attempts`：`is_correct`、`ai_score`、`ai_feedback`
5. 前端展示：对错 + 命中的采分点（绿）+ 遗漏的采分点（红）+ 一句点评

### 返回结构

```json
{
  "score": 78,
  "hit_points": ["教育是有目的地培养人的社会活动"],
  "missing_points": ["未提到促进个体社会化"],
  "correct": true,
  "comment": "要点基本到位，补充社会功能会更完整"
}
```

### 过关判定

`correct = score >= 60` **且** 采分点覆盖率 `>= 0.6`。两个条件同时满足才判对，避免"写了一堆废话骗高分"。

### 必须处理的坑

- **语义等价**：学生表述与参考答案不同但意思一致时必须判对，prompt 里要明确写"按语义判，不按字面"
- **缓存**：`hash(题干 + 用户答案)` 命中则复用结果，重复刷同一答案不重复扣费
- **超时降级**：10s 未返回则降级为自评，不能让用户卡在 loading
- **误判申诉**：允许用户一键翻转（"我认为我答对了"），翻转后写流水并标记 `overridden`，**同时保留原始 AI 判定**——这是后续调 prompt 的样本
- **成本**：单题约 800 tokens，30 题一次练习可忽略；但要统计日均调用量，防死循环刷

## 5. 信息架构与页面

| 编号 | 页面 | 关键元素 | 交互要点 |
|---|---|---|---|
| P1 | 登录 / 注册 | 邮箱、密码、注册 | 未登录一律跳这里 |
| P2 | 考试列表（首页） | 考试卡片：名称、类目数、总题数、过关率、最近练习时间 | 空状态引导"新建考试 → 导入题目" |
| P3 | 考试详情（类目树） | 每个节点显示：题目数 / 已过关数 / 错误率 + 进度条 | 支持一层子类目；只有一个类目时自动跳过此层 |
| P4 | 类目详情 | 按题型分组（单选·多选 / 填空 / 简答），每组显示题单 | 每道题显示过关状态、历史答题次数 |
| P5 | AI 导入 | 大文本框 + 目标类目选择 → 解析中 → 校对表格 → 批量确认 | **核心页面**，见第 6 节 |
| P6 | 练习 | 一题一屏：题干 → 作答区 → 判定反馈 → 下一题 | 顶部进度条；退出保留进度 |
| P7 | 错题本 | 按考试 / 类目筛选，按错误次数排序 | 可一键"只刷错题" |
| P8 | 单题手动录入 | 题型、类目、题干、选项、答案、解析 | AI 解析失败或补录时的兜底 |

## 6. AI 导入设计（核心）

### 输入

多行文本框，粘贴任意文本（教材、真题、笔记、公众号）。可选指定目标类目，不指定则由 AI 推荐。

### 处理链路

1. **文本预处理**：归一化空白与全角标点，去页眉页脚，按题目序号 / 空行粗切
2. **分批**：超长文本按 ~3000 字切块，并发 2–3 块，每块携带"上一块最后一题"的上下文，防止题目被切断
3. **LLM 结构化输出**：JSON Schema 约束的数组，schema 校验失败则带错误信息重试（最多 2 次），仍失败降级为单题重解析
4. **规则校验**：字段完整性；题型与内容自洽（单选必须 ≥3 个选项且答案唯一且在选项内；填空必须有明确的空位标记；简答不应有选项）
5. **去重**：题干归一化（去空白、去标点、小写）后取 hash，与库内已有题目比对，命中则标记「已存在」
6. **类目归并**：把用户该考试下已有类目列表塞进 prompt，强制从里面选；选不到才建议新建（防止类目爆炸成 50 个）

### 单题输出结构

```json
{
  "type": "single_choice | multi_choice | fill_blank | short_answer",
  "stem": "题干原文",
  "options": ["A. ...", "B. ..."],
  "answer": "B",
  "explanation": "解析",
  "category_hint": "教育心理学",
  "confidence": 0.0
}
```

### 人工校对（不可省）

解析结果以表格呈现，逐行可编辑：

- 题型下拉（可改）
- 类目下拉（可改）
- 勾选是否入库（可批量全选 / 仅全选高置信度）
- `confidence < 0.7` 的行高亮
- **必须点"确认导入"才落库**，绝不自动写

### 工程要点（这才是练手的重点）

- **结构化输出可靠性**：schema 校验 → 错误回灌重试 → 降级路径
- **长任务进度**：SSE 或轮询返回"已解析 2/5 段，已得 18 题"
- **成本控制**：token 计数、单次导入题数上限（如 50 题）、超限提示分批
- **可观测性**：记录 prompt 版本、耗时、失败率、平均置信度，便于调 prompt
- **导入任务表**：`import_jobs` 存原始文本、状态、结果，失败可重放

## 7. 数据模型

| 表 | 关键字段 | 说明 |
|---|---|---|
| `users` | id, email, password_hash, nickname, created_at | 邮箱唯一 |
| `exams` | id, user_id, name, description, exam_date, created_at | 首页卡片数据源 |
| `categories` | id, exam_id, user_id, parent_id, name, sort_order | parent_id 支持一层子类目；为 null 即顶层 |
| `questions` | id, exam_id, category_id, type, stem, options_json, answer, explanation, stem_hash, created_at | unique(exam_id, stem_hash) 做去重 |
| `attempts` | id, user_id, question_id, answer_json, is_correct, score, duration_ms, created_at | **答题流水，只增不改**，所有统计从这里算 |
| `import_jobs` | id, user_id, exam_id, raw_text, status, result_json, error, created_at | 导入任务，支持进度与重放 |

### 统计口径（SQL 层）

- 题目数：`count(questions)` where category_id in 子树
- 已过关数：`count(distinct question_id)` from attempts where is_correct = true
- 错误率：`sum(is_correct = false) / count(*)`（按第 4.2 节确认的口径）

**性能坑**：这三个指标每个类目节点都要算，类目多了就是 N+1。建议加一张 `category_stats` 表（category_id, total, passed, error_rate, updated_at），在答题提交后异步重算该节点及其父节点，或定时全量刷新。

## 8. 一期非目标（明确不做）

- 文件上传解析（PDF / Word / Excel）——纯文本粘贴已覆盖大部分场景
- 算法题 / 代码沙箱执行
- AI 生成变式题、自动组卷
- 间隔重复算法（SM-2 / FSRS）
- 考试或题目分享、社区、排行榜
- 移动端原生适配（响应式即可）

## 9. 里程碑

| 阶段 | 内容 | 目的 |
|---|---|---|
| M1 骨架 | 登录 + 考试/类目 CRUD + 单题录入 + 做题 + 统计 + 错题本 | 无 AI，纯 CRUD 跑通全链路，先把数据模型验证对 |
| M2 AI 导入 | 文本解析 + 校对表格 + 去重 + 类目归并 + 任务进度 | 核心差异点落地 |
| M3 判分 | 简答 AI 判分 + 错误率口径 + 统计性能优化 | 补完判题闭环 |
| M4 打磨 | 错题专项刷、练习模式（顺序/随机/只刷未过关/只刷错题） | 手感 |
