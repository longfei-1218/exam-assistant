## 1. 文档职责

本文档只负责前端范围，包括页面结构、路由、交互流程、接口消费、状态管理和浏览器端验收。

数据模型、接口实现、鉴权、LLM Provider、AI 导入任务、简答判分和数据库迁移以后端实施计划为准；字段级契约、状态机与错误码以[后端技术实现文档.md](./后端技术实现文档.md)为准。前后端共享的类型与 Schema 放在 `packages/shared`，前端不得复制一份独立定义。

当前阶段以“前端主体已完成、后端持续补齐”为基线。后端接口未完成时，前端可以使用本地演示数据或 mock 数据，但接口形态必须与后端计划保持一致。

字段命名约定：请求与响应统一 camelCase，与现有 `apps/web/src/types.ts` 的对象名、字段名保持一致；后端响应可为前端类型的超集，前端按需取用。

## 2. 一期范围与边界

前端需要覆盖：

1. M1：登录、考试、类目、题目 CRUD、客观题作答、错题本、统计。
2. M2：AI 文本导入、解析进度、结果校对、去重提示、类目归并展示。
3. M3：简答题作答、AI 判分结果展示、采分点反馈、申诉翻转。

一期不包含：

- 真实邮件发送和邮箱验证
- PDF、Word、Excel 文件解析
- 算法题和代码题
- AI 变式题和自动组卷
- SM-2、FSRS 等间隔重复算法
- 练习进度跨页面或跨设备恢复
- 题目分享、社区、排行榜
- 移动端原生应用

## 3. 前端已确认决策

| 决策项 | 结论 |
| --- | --- |
| 产品形态 | 移动优先的响应式 Web |
| 客户端技术 | React 19、Vite、TypeScript、React Router |
| UI | Ant Design 6、Tailwind CSS |
| 数据请求 | TanStack Query |
| 表单与校验 | React Hook Form、Zod，共享 Schema 优先复用 `packages/shared` |
| 登录 | 邮箱密码注册登录，找回密码只做 UI 和 token 流程 |
| LLM 密钥 | 用户自带 Key 正式启用，在设置页随用户信息配置；前端不明文存储，回显用掩码 |
| AI 异步导入 | 创建任务后每 1.5 秒轮询 `GET /api/imports/:id` |
| 练习进度 | 不持久化，不恢复进度 |
| 验收方式 | 类型检查、组件测试、Playwright 冒烟测试 |
| 初始内容 | 不内置种子题库 |

## 4. 前端技术架构

### 4.1 技术栈

- 构建：Vite
- 框架：React 19、TypeScript
- 路由：React Router
- UI：Ant Design 6、Tailwind CSS
- 服务端状态：TanStack Query
- 表单：React Hook Form
- 校验：Zod
- 测试：Vitest、Playwright

### 4.2 目录结构

```text
apps/web/
├── src/
│   ├── pages/
│   ├── components/
│   ├── auth/
│   ├── api/
│   ├── styles/
│   ├── App.tsx
│   └── main.tsx
└── package.json

packages/shared/
├── schemas/
├── types/
└── llm-contracts/
```

### 4.3 分层约定

- 页面只处理路由、查询组合和交互状态。
- 可复用展示组件放在 `components`。
- HTTP 调用集中在 `api`，页面不直接拼接请求地址。
- 登录态由 `auth` 统一提供，页面不单独读取 token。
- 业务类型从 `packages/shared` 导入，避免与后端定义漂移。
- TanStack Query 管理服务端数据，认证用户等客户端状态由本地上下文管理。

## 5. 页面与路由

| 路由 | 页面 | 主要能力 |
| --- | --- | --- |
| `/login` | 登录注册 | 登录、注册、表单校验、登录后跳转 |
| `/` | 考试列表 | 新建、编辑、删除考试，进入考试与练习 |
| `/exams/:examId` | 考试详情 | 类目树、统计概览、新建和编辑类目 |
| `/exams/:examId/categories/:categoryId` | 类目题单 | 题目列表、单题录入、编辑和删除 |
| `/practice/:examId` | 练习作答 | 单选、多选、填空、简答及结果反馈 |
| `/import/:examId` | AI 导入 | 原文提交、目标类目选择、任务进度 |
| `/wrong-book` | 错题本 | 按类目筛选、待订正和已订正列表 |
| `/settings` | 个人设置 | 头像、昵称、模型配置、退出登录 |

所有业务路由均要求登录。未登录访问业务页面时跳转 `/login`。

首页顶部导航最右侧显示当前用户头像，点击后进入 `/settings`。个人设置页至少包含：

- 头像上传与移除
- 昵称编辑
- 模型供应商选择，目前仅支持 DeepSeek
- 模型名称选择，目前支持 DeepSeek Flash 和 DeepSeek Pro（`deepseek-chat` / `deepseek-pro`）
- 个人模型 API Token 输入、粘贴、显示和隐藏；已配置时显示后端返回的掩码 `apiTokenMasked`（如 `sk-****abcd`），**不回显明文**
- 未修改 Key 时保存**不要传 `apiToken`**，避免清空已配置密钥；传空串或 `null` 表示主动清空
- 可选：保存前调用 `POST /api/auth/llm-config/verify` 校验连通性，失败提示重新输入
- 保存设置（调用 `PATCH /api/auth/me`）
- 退出登录并返回 `/login`

**安全要求**：Token 输入框使用 `type="password"`；明文 Key 只存在于本次编辑的内存态，提交后清除；**严禁写入 localStorage / sessionStorage / IndexedDB**（现有 mock 的明文存储需整改）。

前端依赖以下接口，详细字段和校验规则见后端计划：

| 认证 | `POST /api/auth/refresh` |
| 认证 | `POST /api/auth/logout` |
| 认证 | `GET /api/auth/me` |
| 认证 | `PATCH /api/auth/me`（设置页保存昵称 / 头像 / 模型配置 / 加密 Key） |
| 认证 | `POST /api/auth/llm-config/verify`（Key 连通性校验，可选） |
| 考试 | `GET/POST /api/exams` |
| 考试 | `GET/PATCH/DELETE /api/exams/:id` |
| 类目 | `GET/POST /api/categories` |
| 类目 | `PATCH/DELETE /api/categories/:id` |
| 题目 | `GET/POST /api/questions` |
| 题目 | `GET/PATCH/DELETE /api/questions/:id` |
| 作答 | `POST /api/attempts` |
| 作答 | `GET /api/questions/:id/attempts` |
| 作答 | `POST /api/attempts/:id/override`（简答自评 / 申诉翻转） |
| 练习 | `POST /api/practice/session` |
| 错题本 | `GET /api/wrong-book` |
| 导入 | `POST /api/imports` |

| 导入 | `POST /api/imports/:id/retry`（失败任务重放） |
| 统计 | `GET /api/stats/:examId` |

每个接口的请求参数、响应结构、错误码与状态副作用见[后端技术实现文档.md](./后端技术实现文档.md)第 6 章。

前端需要统一处理：

- 401（`UNAUTHORIZED` / `TOKEN_EXPIRED`）时清理登录态并跳转登录页
- 统一错误响应结构 `{ statusCode, code, message, details, requestId }`，按 `code` 映射中文提示
- **`LLM_KEY_NOT_CONFIGURED` / `LLM_KEY_INVALID` 特殊处理**（见下方 6.2）
- 请求 loading、空状态和错误提示
- 表单字段错误与服务端校验错误（`VALIDATION_ERROR` 的 `details`）
- 导入任务状态 `queued`、`processing`、`ready`、`confirmed`、`failed`，按 `progressJson` 渲染进度、`resultJson` 渲染校对表格
- 题单 `answerState`（`passed` / `wrongCount` / `answerCount`）三态展示：已过关 / 未过关·错 N 次 / 未作答
- 简答题 `isCorrect = null` 表示待自评，AI 判分超时后切换自评降级
- 简答结果 `overridden = true` 的条目显示"已申诉"，不再提供翻转入口

### 6.1 待确认的前后端差异

| 项 | 前端现状 | 一期后端（实际实现） | 处理 |
| --- | --- | --- | --- |
| 练习进度 | 设计稿 P8 有"退出保留进度 / 断点续答" | 不持久化、不恢复（见第 2 节） | 练习页不提供进度保存入口，进度条仅表示本次会话内进度；去掉"保存进度"弹层或标注二期 |
| Attempt 类型 | `isCorrect: boolean` | 简答待自评时为 `null` | `apps/web/src/types.ts` 的 `Attempt.isCorrect` 改为 `boolean \| null`，并补充 `aiScore` / `aiFeedback` / `answerHash` / `originalAttemptId` 字段 |
| 题单作答状态 | `Question` 无作答状态字段 | `GET /api/questions` 附带 `answerState` | 扩展 `Question` 类型，题单直接消费后端字段，避免 N+1 请求 |
| 密钥存储 | mock 把 `apiToken` 明文写入 localStorage | Key 加密落库、响应只回掩码 | 整改 mock：移除 localStorage 中的明文 Key；`AuthUser.llmConfig` 改为 `configured` + `apiTokenMasked`，移除明文字段 |

> LLM Key 已定案：用户自带 Key 正式启用，见 6.2 与设置页说明。

### 6.2 密钥缺失的配置引导（重点）

调用 AI 能力的两个入口——**AI 导入**（`POST /api/imports`）和**简答判分**（`POST /api/attempts` 简答分支）——后端在入口同步校验 Key，未配置 / 无效时返回专用错误码。前端统一拦截并按以下规则处理：

| 错误码 | 触发时机 | 弹窗文案 | 按钮 |
| --- | --- | --- | --- |
| `LLM_KEY_NOT_CONFIGURED` | 未配置 Key 时使用 AI 功能 | "该功能需要配置大模型密钥" | 配置 / 取消 |
| `LLM_KEY_INVALID` | Key 错误、额度不足、连通失败 | "大模型密钥无效或额度不足，请重新配置" | 配置 / 取消 |

交互流程：

1. 请求拦截器按 `code` 匹配，**优先级高于**通用错误提示与 401 处理（这两个码不清理登录态、不跳登录页）。
2. 命中后弹出确认框，正文取后端 `message`，`details.feature` 用于补充"AI 导入 / 简答判分"的场景描述。
3. 点"**配置**"：跳转 `details.settingsPath`（`/settings`），进入个人设置页配置 Key。
4. 点"**取消**"：关闭弹框，停留当前页面，不做跳转。
5. 配置完成后返回原页，**不自动重放**原操作（一期无进度恢复），由用户重新发起。
6. 前端可在发起前读取 `GET /api/auth/me` 的 `llmConfig.configured` 做前置提示，但**必须保留对后端错误码的处理**（Key 可能在别处被清空或失效）。

> 短路判错（空 / 短答案）与缓存命中不校验 Key，不受密钥缺失影响，前端无需为这两种情况弹框。

详细错误响应结构与时序图见[后端技术实现文档.md](./后端技术实现文档.md)第 6.10 节。

## 7. 分步实施计划

### 第 1 步：工程基线

- 初始化 pnpm workspace。
- 初始化 `apps/web`。
- 接入 TypeScript、ESLint、Prettier、Vite、Tailwind CSS、Ant Design 6。
- 配置 React Router、TanStack Query 和共享类型包。
- 建立移动优先的页面容器和全局样式。

验收：前端可启动、可通过类型检查和生产构建。

### 第 2 步：登录注册

- 实现登录和注册双模式页面。
- 校验邮箱、密码、确认密码和昵称。
- 登录成功后保存会话并跳转考试列表。
- 未登录访问业务页面时跳转登录页。
- 提供退出登录入口。

验收：登录、注册、退出和路由守卫行为正确。

### 第 3 步：考试与类目

- 实现考试列表、创建、编辑和删除。
- 实现考试详情页和统计卡片。
- 实现顶层类目与一层子类目的创建、编辑和删除。
- 删除前提供确认弹窗。

验收：考试和类目数据变化后列表与统计同步刷新。

### 第 4 步：题目录入与题单

- 支持单选、多选、填空、简答四种题型。
- 根据题型切换选项、答案和解析输入区域。
- 展示题目数量、已过关数和错误率。
- 支持题目编辑和删除。
- 服务端返回重复题干时展示明确错误。

验收：四种题型均可录入、编辑和删除。

### 第 5 步：练习作答

- 展示题号、总题数和进度条。
- 单选使用单选组，多选使用复选组。
- 填空使用单行输入，简答使用多行输入。
- 提交后展示正确、错误或待 AI 判定状态；`isCorrect = null` 时展示自评入口。
- 展示解析、采分点、遗漏点和点评。
- 简答结果通过 `POST /api/attempts/:id/override` 申诉翻转，`overridden = true` 后不再展示翻转入口。
- 简答提交命中 `LLM_KEY_NOT_CONFIGURED` / `LLM_KEY_INVALID` 时弹出配置引导框（见 6.2）。
- 进度条仅表示本次会话内进度，不提供"保存进度 / 断点续答"入口（见 6.1）。

验收：客观题可即时反馈，简答题可展示结构化判分结果，超时可自评，申诉入口状态正确，未配置密钥时能正确引导配置。

### 第 6 步：统计与错题本

- 展示考试、类目和整体错误率。
- 错题本支持按类目筛选。
- 待订正和已订正分组展示。
- 支持从错题本直接进入错题练习。
- 答对后题目移入已订正，不计入待刷数量。

验收：统计口径与产品定义一致。

### 第 7 步：AI 导入与校对

- 提交原始文本和目标类目。
- 创建导入任务后每 1.5 秒轮询任务状态。
- 展示已解析分段、题目数量和错误信息。
- 支持编辑题型、类目、题干、选项、答案和解析。
- 低置信度题目高亮。
- 重复题默认不勾选。
- 用户确认后才提交批量落库。
- 创建任务命中 `LLM_KEY_NOT_CONFIGURED` / `LLM_KEY_INVALID` 时弹出配置引导框（见 6.2），不进入轮询。

验收：确认前不会写入题目，任务失败后可重新提交，未配置密钥时能正确引导配置。

### 第 8 步：个人设置与模型配置

- 支持选择本地图片作为头像并即时预览。
- 支持编辑昵称。
- 模型供应商仅提供 DeepSeek。
- 模型名称仅提供 DeepSeek Flash 和 DeepSeek Pro。
- API Token 支持输入、粘贴、隐藏和显示；已配置时显示掩码 `apiTokenMasked`，不回显明文。
- 可选：保存前调用 `POST /api/auth/llm-config/verify` 校验 Key 连通性，失败提示重新输入。
- 未修改 Key 时保存不传 `apiToken`，避免清空已配置密钥；明文 Key 不写入任何本地存储。
- 保存调用 `PATCH /api/auth/me`，成功后更新当前会话和顶部头像。
- 退出登录需要二次确认。

验收：刷新页面后头像、昵称、模型配置和密钥配置状态仍保留；localStorage 中无明文 Key。

### 第 9 步：前端自动化验收

Playwright 覆盖：

- 登录
- 创建考试
- 手动录题
- 客观题作答
- AI 导入校对
- 简答提交

验收：关键用户路径无阻断错误。

## 9. 前端风险与处理

| 风险 | 处理 |
| --- | --- |
| 接口字段频繁变化 | 以 `packages/shared` 为准，前端集中维护请求层 |
| 导入轮询造成重复请求 | 使用 TanStack Query 的固定查询键和轮询间隔 |
| 长文本校对页面卡顿 | 分块渲染或虚拟列表，编辑状态单独保存 |
| AI 判分超时 | 展示处理中状态，10 秒后切换为自评 |
| 移动端输入框被键盘遮挡 | 使用页面内滚动和底部安全间距 |
| 大模型 Token 暴露风险 | 明文仅存于编辑态内存，提交后清除；**不写 localStorage / sessionStorage / IndexedDB**；输入框用 `type="password"`，不拼进 URL 或错误上报 |
| 未配置密钥导致操作失败 | 拦截专用错误码弹配置引导框，配置 / 取消分支明确；不误触 401 退出逻辑 |
| 前后端错误提示不一致 | 统一使用共享错误结构和错误码 |

## 10. 本地启动

```bash
pnpm install
pnpm --filter @exam/web dev
```

后端未启动时使用 mock 数据完成页面开发和交互验收。联调时先启动 PostgreSQL 和 API，再启动 Web。

## 11. 交付给后端的约束

- 所有业务接口必须返回统一错误结构 `{ statusCode, code, message, details, requestId }` 和可供前端区分的错误码。
- 所有业务接口都必须验证用户身份，并按 `user_id` 过滤数据。
- 请求与响应字段统一 camelCase，与 `apps/web/src/types.ts` 现有对象名、字段名保持一致。
- 导入任务必须返回稳定状态和进度字段（`progressJson`、`resultJson`，含 `confidence`、`duplicate`）。
- 题单接口需附带 `answerState`（`passed` / `wrongCount` / `answerCount`）。
- `attempts.isCorrect` 允许 `null`（待自评）；简答判分返回分数、采分点、遗漏点、点评和最终判定。
- `AuthUser.llmConfig` 只返回 `configured` + `apiTokenMasked`，不返回明文 Key。
- AI 接口返回 `LLM_KEY_NOT_CONFIGURED` / `LLM_KEY_INVALID`，`details` 带 `feature` 与 `settingsPath`。
- 题目类型、导入状态和判分结果类型必须进入 `packages/shared`。

前端据此需要同步 `apps/web/src/types.ts`：

- `Attempt.isCorrect` 改为 `boolean | null`，补充 `answerJson`、`score`、`aiScore`、`aiFeedback`、`overridden`、`originalAttemptId`、`durationMs`、`answerHash` 字段；`Question` 补充可选 `answerState`。
- `AuthUser.llmConfig` 改为 `{ provider, model, configured, apiTokenMasked }`，移除明文字段 `apiToken`；设置页提交新 Key 时用独立的请求字段。

详细字段定义见[后端技术实现文档.md](./后端技术实现文档.md)第 6.1、6.4、6.5、6.10 节。
